## 三、剩余 17 FAIL + 7 ERROR 根因归属（诚实判定）

### 17 FAIL —— 全部为 `text_contains: 找到0个匹配文本节点`

| 归属 | 判定 |
|---|---|
| **AI 断言语义精度（引擎智能边界）** | needle 是 AI 对预期结果的**转述**（如"系统拒绝访问（403）"是超长散文、"顶部显示「共 N 条」"是模板占位符），页面真实行为正确但无该字面文本。占位符/超长散文两类已由本轮新守卫（`_check_guard` needle 可靠性校验）在**下一轮生成时**剔除 |
| **非靶子缺陷** | 逐条核验页面实际行为均正确（如登录失败确实拒绝了访问），无一条是产品真实 bug |
| 结论 | 引擎机械执行层无罪；是"AI 生成的断言措辞 vs 页面字面文本"的语义对齐问题。根治方向=语义匹配断言（已在待办），非本轮补丁范围 |

### 7 ERROR —— Agent 多步执行失败

多步异常/边界/行为流场景（如连续多步表单交互+状态断言），Agent 在步数/上下文预算内未走完验证链。属**Agent 执行深度能力边界**（本地 qwen2.5:7b 推理深度 + 循环预算），非靶子缺陷、非机械假 FAIL。提升路径：更强的执行模型（云端双路由）或提高循环预算，二者均为产品级决策。

### SKIP 2 —— 引擎覆盖缺口守卫（正常工作）

`_engine_coverage_gap` 将"Agent 仅 replay 缓存、无实时动作"的用例诚实改判 SKIP 而非假 FAIL——守卫按设计工作。
