## 四、诚实披露：尚未闭合的问题（不夸大）

1. **控件语义定位缺口（影响"需求用例可执行"）**
   需求侧动作文案为"点击操作按钮**查询**"，靶子实际按钮为 `data-testid=btn-search` 文案"**搜索**"。
   `_guided_click` 依次尝试 `getByRole(button,name=target)` → 关键词匹配 → `_semantic_menu_match`，
   但 `[SemanticMenu]` 在日志中**零出现** → 语义匹配未真正生效（LLM 调用未命中或静默失败）。
   后果：`TC-REQ-001-I02/I03` 判 **ERROR**（"点击'查询'失败: 未找到按钮"）。
   这是"智能=真实 LLM 调用"的目标缺口，**未修复**。

2. **通配 API 探针伪造 URL**
   通用探针 `api_call_count_check{url_pattern:".*"}` 被当真 URL 探测 →
   `executions.actual = "404"`。引擎已诚实降级为 SKIP（不记假 FAIL），但污染结果语义。

3. **`db_table_accessed_check` 在 ADI 46 族中仍 unresolved**
   已注册执行器（能跑），但未登记为 taxonomy 族。**故意未强行映射**：它本质是浅探针，
   强行归入值级族（score 3）会高估深度。属诚实标注，非遗漏。

4. **`fcp` 的 `ON_NAVIGATE` 发射点仍缺失**
   `performance_monitor.on_navigate` 采集 FCP 的分支无人触发；D26 改为在 `_UI_CHECK_DISPATCH`
   直接测量并写入 `fcp` 指标，但 `performance_monitor` 路径本身仍为死代码。

5. **Step5（报告/补测建议/可下载）未验证**
   依赖 Step4 完成。完成后需执行：
   `POST /api/step/5 {"project":"accept_sut_0923"}` → 校验报告页 + 下载端点。

6. **§14 复核待办**：D24~D29 六项改动均属核心路径/DB 写，**待强模型（GLM-4.5 / DeepSeek-V4-Pro）复核**。
