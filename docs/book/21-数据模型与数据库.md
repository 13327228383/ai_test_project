# 第 21 章　数据模型与数据库

## 概述

数据层由三块构成：`src/core/schema.sql`（MySQL 全量 DDL，94 个 `CREATE TABLE` 命中行中 4 行为注释、实测 **90 张真实表**）、`src/core/db_manager/`（连接池与事务包装）、以及 `paths/`、`session_context/`、`utils/` 等支撑模块。本章先按业务域分组 90 张表并标注主键与关键外键，再说明连接与事务机制、命名规范、旧名对照。

> 实测表数：Grep `CREATE TABLE` 命中 94 行（`schema.sql` 全文），其中 `schema.sql:6`、`:1495`、`:1567`、`:1991` 四行为注释文本，非建表语句，故真实表数为 **90**。与大纲/AGENTS.md 所述「94 张表」不符，以当前代码为准。

## 数据库连接与事务管理

- 连接池：`src/core/db_manager/_pool.py` 使用 `dbutils.pooled_db.PooledDB`（`_pool.py:67-79`），上限 `_MAX_POOL=60`，`mincached=5`、`maxcached=20`、`maxshared=0`、`ping=1`、`blocking=False`。`autocommit=False`（`_pool.py:37-48`），连接超时 `_CONNECT_TIMEOUT=10`、读超时 `_READ_TIMEOUT=30`，池满重试 `_MAX_RETRIES=5`（`:17-24`）。
- 游标：`pymysql.cursors.DictCursor`，返回字典行（`_pool.py:10,44`）。
- 取连接入口：`db_manager/__init__.py:47` 的 `get_connection()`。
- 事务包装：`_wrapper.py:9` 的 `_PooledConnectionWrapper` 提供 `execute/fetchone_sql/fetchall_sql/commit/rollback`；`__enter__/__exit__` 在异常时 rollback、正常时 commit（`_wrapper.py:101-109`）。`_AutoCloseCursor`（`:112`）读完即自动关闭。
- 启动建表：`db_manager/_utils.py:55` 的 `init_schema_on_startup()` 首次连接执行 `schema.sql`（`schema.sql:6` 注释）。
- 健康检查：`_utils.py:71` 的 `health_check()`；连接追踪：`_utils.py:13-44` 的 `_track_connection/_untrack_connection/release_thread_connections`。

## 命名规范

- 表名无统一前缀，按业务实体命名（复数或单数混用：`projects`/`users`/`executions`/`case_meta`）。
- 列名 snake_case；跨项目表统一以 `project VARCHAR(128)` 作维度键，外键指向 `projects.name`，且 **`ON DELETE CASCADE`**（`schema.sql:7` 注释 + 各表 FK）。
- 版本隔离列固定为 `version_id BIGINT DEFAULT 0`（`0=legacy`），指向 `project_versions.id`。
- 引用用例固定列 `case_id VARCHAR` 指向 `test_cases.case_id`；引用用户固定列 `user_id VARCHAR(64)` 指向 `users.id`。
- 灵活载荷用 `JSON` 或 `LONGTEXT` 列（`payload_json`/`config_json`）；哈希列 `_hash` 多为 MD5。

## 设计取舍

- 单库单 schema 统一管理：所有 DDL 收口到 `schema.sql` 一处（`schema.sql:1-8`），消除各 store 文件分散建表的历史问题（墓碑注释如 `:689` `semantic_index`、`:714` `db_schema_catalog` 已删除）。
- 项目级 `ON DELETE CASCADE`：删项目级联清理全部维度数据，降低孤儿数据风险，代价是删除不可逆。
- 版本隔离用 `version_id` 而非分表：同一库内多版本共存，查询需始终带 `project`+`version_id` 维度。
