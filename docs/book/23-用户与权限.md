# 第 23 章　用户与权限

## 概述

本章描述 E2E 智能测试引擎的用户体系与权限模型。用户数据集中在 `users` 表，角色与权限分离存储于 `roles`/`user_roles`/`role_permissions`，项目级授权通过 `project_members` 实现。登录密码使用 SHA-256（无盐）存储，登录态保存在 MySQL 的 `flask_sessions` 表。LLM API Key 等业务凭证与登录密码物理隔离，单独存于 `user_credentials_v2` 并以 Fernet 加密。

## 用户模型与存储

用户主表为 `users`（`src/core/schema.sql:52`），主键 `id`，字段含 `name`、`password`、`created_at` 等。代码侧的用户常量在 `src/users/_user_db_core.py` 定义，`ALLOWED_ROLES = ("admin", "project_admin", "project_member")`（`src/users/_user_db_core.py:7`）。

与用户相关的数据表：

| 表名 | 职责 | 关键键 |
| --- | --- | --- |
| `users` | 用户主表，存登录名、密码哈希、姓名 | PK `id` |
| `roles` | 角色定义种子表 | PK `id` |
| `user_roles` | 用户-角色多对多映射 | FK `user_id`→`users.id`，`role_id`→`roles.id` |
| `role_permissions` | 角色-权限映射 | FK `role_id`→`roles.id` |
| `role_projects` | 角色-项目关联（已弃用） | FK `role_id` |
| `project_members` | 项目成员与项目内角色（owner/member） | FK `user_id`→`users.id`，`project`→`projects.name` |
| `user_credentials_v2` | 用户业务凭证（如 LLM API Key），加密存储 | FK `user_id`→`users.id` |
| `login_tracking` | 登录失败计数与锁定记录 | FK `user_id`→`users.id` |
| `flask_sessions` | Flask 登录会话，持久化到 MySQL | 会话表 |
| `api_tokens` | API 令牌，含 `created_by`→`users.id` | FK `created_by` |

`role_projects` 在代码中已不再使用：`get_role_projects` 直接返回空列表（`src/users/role_rbac/_permission.py:90-95`），项目级授权改走 `project_members`。

## 密码存储与强度策略

登录密码的哈希函数为 SHA-256，无加盐：`_hash` 实现为 `hashlib.sha256(password.encode("utf-8")).hexdigest()`（`src/users/auth/password.py:139-144`）。

密码强度在注册与修改时校验：`validate_password_strength` 要求长度 ≥8、同时含字母与数字，并命中弱密码黑名单则拒绝（`src/users/auth/password.py`）。`create_user` 在执行前调用该校验（`src/users/user_crud.py:11`）。

`users` 表 DDL 中曾出现的 admin 占位哈希 `240be518...`（`src/core/schema.sql:1366`）的注释标注为“已从 DDL 移除”，即数据库初始化不写入该账号。

## 角色与权限边界（RBAC）

系统角色共三种：`admin`、`project_admin`、`project_member`（`src/users/_user_db_core.py:7`）。

权限判定入口在 `src/users/project_auth.py`：
- `is_admin`（`src/users/project_auth.py:263`）：系统级管理员。
- `is_project_admin`（`src/users/project_auth.py:286`）：admin，或项目级 `project_admin`，或该项目的 owner/admin。
- `is_project_member`（`src/users/project_auth.py:324`）：项目成员。
- `get_user_system_role`（`src/users/project_auth.py:347`）：系统角色优先级 `admin > project_admin > project_member > custom`。

角色权限从 `role_permissions` 读取（`get_role_permissions`，`src/users/role_rbac/_permission.py:7`）。`set_user_roles_bulk` 在执行前保护“最后一个 admin”不被降级或删除（`src/users/role_rbac/_permission.py:183-229`）。`/api/permissions/role/<role>` 仅 admin 可调（`src/backend/routes/auth/_permission.py:106`），`/api/users/<user_id>/role` 需要 `user.role.set` 权限（`:128`）。

## 登录与会话机制

登录入口 `/api/login`（`src/backend/routes/auth/_login.py:29`）接受 `user_id` 或 `username` 别名。校验使用 SHA-256 比对（`src/users/auth/login.py:55`）。

失败次数限制来自 `src/users/auth/rate_limit.py`：`MAX_FAILED_ATTEMPTS = 5`、锁定时长 `LOCK_DURATION_MINUTES = 15`（`:12-13`）。`check_login_rate` 在登录前拦截，连续 5 次失败后账号锁定 15 分钟；`record_login_failure` 写入 `login_tracking`（`:82`）。

登录成功后写入 `session["user_id"]` 并置为 permanent（`src/backend/routes/auth/_login.py:87-92`）。会话存储介质为 MySQL 的 `flask_sessions` 表，而非内存或文件。登录做了会话固定保护（清空旧会话再写入，`_login.py:87`）。登出设 3 秒冷却，防止重放（`_login.py:58-66`）。当前登录态可由 `/api/current-user` 取回（`:194`）。

## 注册与账号初始化流程

注册有两个入口：
- `/api/users`（POST，`:67`）：创建用户，`user_id`（或别名 `username`）、`name`、`password` 必填（`:83-90`），默认角色参数在调用处传入。
- `/api/register`（POST，`:152`）：带角色授权逻辑的注册入口。

`/api/register` 的角色分配规则（`src/backend/routes/auth/_user.py:205-217`）：
- 调用者为 `admin`：可按请求分配 `admin` / `project_admin` / `project_member`。
- 调用者为 `project_admin`：新用户固定为 `project_member`，并分配到指定项目。
- 其他调用者：新用户固定为 `viewer`。

`create_user`（`src/users/user_crud.py:11`）做密码强度校验、用户名正则 `^[a-zA-Z0-9_\-一-鿿]+$` 校验，默认角色 `project_member`。`delete_user` 同样保护最后一个 admin（`:240`）。

首启 admin 初始化走 `ensure_bootstrap_admin`（`src/users/bootstrap.py:66`）：密码解析顺序为环境变量 `BOOTSTRAP_ADMIN_PASSWORD` → 配置 `BOOTSTRAP_DEFAULT_PASSWORD` → 随机 16 位；临时密码记入日志并要求首次登录修改。代码中不存在硬编码的 `admin/admin123`。

## 凭证隔离（LLM API Key 等）

业务侧凭证（LLM API Key 等）与登录密码物理隔离：登录密码在 `users.password` 用 SHA-256 存储；业务凭证在 `user_credentials_v2`，以 Fernet 对称加密存储（`src/users/auth/encryption.py`，密钥优先取自 `system_config` 表，其次环境变量 `ENCRYPTION_KEY_V2`，再次备份文件，最后仅在没有密文时生成，`src/users/auth/encryption.py:148-231`）。

读取逻辑 `get_user_credential`（`src/users/credentials.py:34`）按优先级查找：当前项目 → 用户全局（`*`）→ admin 全局（`*`）。写入经 `_encrypt_auto` 加密（`:69`）。该隔离保证业务密钥不参与登录校验，也不随登录密码策略变更而泄露。

## 操作审计日志（audit_logs）

用户与权限体系的写操作留有审计轨迹，落在 `action_logs` 表。模块入口是 `src/users/audit_logs/`（facade `__init__.py`，导出 6 个符号）。

- **写入**：`log_action(user_id, action, *, scope_type, scope_id, detail, ip_address)`（`_action_logs.py:234`）。`scope_type` 仅接受 `system`/`project`/`user`/`global`，且 `project`/`user` 必须带 `scope_id`（`_normalize_scope`，`:18-27`）；`detail` 为 dict/list 时直接 JSON 序列化，否则包装为 `{"message": ...}`（`:248-253`）。`user_id` 为空则直接返回（`:244`）。落库语句写入 `action_logs(user_id, action, scope_type, scope_id, detail, ip_address, created_at)`（`:259`）。
- **调用面**：全仓引用 `log_action` 的行共 **62 行**（含 `import` 与调用，静态 grep 计数），覆盖登录/登出（`auth/_login.py:172`）、凭证写入（`auth/_key.py:141`）、角色与权限变更（`auth/_permission.py:155`、`auth/_role.py:33`）、流水线步骤执行（`backend/executor/_run_step.py:338`）。登录/登出为不阻塞响应做了后台线程异步化（`_log_action_safe`，`auth/_login.py:19-26`；`threading.Thread(daemon=True)`，`:115-121`）。
- **容量治理**：`_cleanup_action_logs`（`_action_logs.py:36`）保留最近 `ACTION_LOG_RETENTION_DAYS = 90` 天且全表最多 `ACTION_LOG_MAX_ROWS = 100000` 行（两常量定义在 `src/users/_user_db_core.py:8-9`）；采用降频策略，每 `_CLEANUP_EVERY_N = 100` 次 `log_action` 才清理一次（`_action_logs.py:30-45`），降低 MySQL 写压力。
- **查询接口**：`list_action_logs`（`_action_logs.py:104`）、`count_action_logs`（`:64`）、`list_login_tracking`（`:164`）、`count_login_tracking`（`:210`）供控制台读取。登录失败记录单独落 `login_tracking` 表（与 `auth/rate_limit.py` 的失败计数同源）。
- **配置变更历史**：`_config_history.py` 另设 `record_config_change`（`:15`）、`get_config_history`（`:62`）、`rollback_config(project, key, target_value, user_id)`（`:100`）三函数，支持按 `(project, key)` 回滚到历史值——这是配置审计与回退的落点（配置体系见第 22 章）。

## 设计取舍

- 登录密码采用 SHA-256 无盐，而非 bcrypt/argon2。优点是实现与既有数据兼容、校验简单；缺点是抗暴力破解弱于慢哈希，依赖 `login_tracking` 的失败锁定补偿。
- 会话持久化到 MySQL（`flask_sessions`），而非签名 Cookie。优点是多实例共享、可主动失效；缺点是每次请求需查库，引入会话存储依赖。
- 系统角色与项目角色解耦：`user_roles` 表达系统级角色，`project_members` 表达项目级授权，避免跨项目越权。
- 业务凭证独立加密表，使“用户身份”与“第三方密钥”两套信任域分离，轮换互不影响。
