# 第 28 章　关键设计一 · 防幻觉体系

## 概述

E2E 智能测试引擎的需求拆解（Step2）把自然语言文档转成结构化需求 `TestCase` 的前身 `requirements` 表。这一环节的核心风险是 LLM 编造原文没有的需求（幻觉）——模型在整文档上自由生成时，会补全、泛化、臆造条目，使下游用例建立在虚假需求之上。本章讲清四道防线：小切片提取、两阶段原文核对、强制溯源字段、结构置信度打分，以及置信度如何驱动三车道路由与人工闸门。

## 问题：需求拆解为什么产生幻觉

早期整文档一次性喂给 LLM，由模型直接输出完整需求列表。长上下文下模型倾向"补全省略、合并隐含、臆造字段"，且输出与原文无强制绑定，无法回证。Step2 的防幻觉不是靠更多 AI 辩论，而是靠"缩小 AI 作用面 + 零 AI 事实校验"（见 `confidence_scorer.py:9` 的模块说明）。

## 机制一：功能清单驱动 + 小切片提取

`feature_driven_breakdown`（`src/pipeline/steps/step2/analyzers/feature_driven.py`）的流水线为：切片 → AI 提取三元组 → 覆盖率 → 去重 → 5a 原文核对 → 逆向覆盖 → 编号（阶段 1–7，`feature_driven.py:109`）。AI 只负责从每个 ≤600 字的小切片中提取 `(operation, condition, expected_feedback)` 三元组，不再承担大纲识别或全文兜底。

切片上限 `_CHUNK_MAX_CHARS` 默认 600，取自 `pipeline_config.step2_chunk_max_chars`（`_fd_chunking.py:24`）。选择 600 字的依据：满足 §7"AI 输入 ≤600 字"硬约束（`_fd_chunking.py:254` 注释）；原 1200 字（2×max）会导致 AI 输入超限与上下文碎片化。切片按章节切、超长二次切，合并后严格不超过 `max_chars`（`_fd_chunking.py:246`）。

## 机制二：两阶段原文核对

**前向子串匹配（5a）。** `_verify_source_quotes_in_chunks`（`_fd_verification.py:38`）校验每条需求的 `source_quote` 在其所属切片中是否存在，而非在全文 `raw_text` 中匹配——避免 30 万字段长文误命中（`_fd_verification.py:44`）。匹配分三级：当前切片精确子串（`passed`，`:118`）→ 扩展切片（当前+前+后片）精确子串（`passed_extended`，`:127`）→ 前 50% 字符部分匹配（`partial_match`，`:134`）。扩展切片用于解决 AI 跨切片摘录被误判 `unverified` 的问题（根因 E 修复，`:48`）。

**三级信任模型。** `is_implicit=0`（L1 显式）必须核对 `source_quote`；`is_implicit∈{1,2}`（L2 通用隐性、L3 业务隐性）跳过核对、标记 `skipped_implicit`（`_fd_verification.py:55`、`:89`）。隐性需求本就无原文出处，强制核对只会制造假失败。

**逆向覆盖。** `_check_reverse_coverage_v2`（`_fd_verification.py:307`）从 `rag_chunks` 读取 `type='feature'` 且 `is_active=1` 的功能块，检查是否被需求覆盖；未覆盖块标记 `uncovered`，提示可能遗漏。匹配规则为 `feature_id` 命中或关键词出现在需求描述中（`:383`、`:390`）。

## 机制三：source_quote 强制溯源

`source_quote` 字段在生成阶段被要求从切片逐字摘录（`feature_driven.py:10`），5a 在切片中校验。核对结果写入 `_verify_status`（`passed`/`passed_extended`/`partial_match`/`unverified`/`empty_quote`/`skipped_implicit`），该字段后续被置信度打分直接消费（`confidence_scorer.py:186`），形成"摘录 → 校验 → 评分"的可追溯链。

## 机制四：结构置信度打分

`compute_confidence_scores`（`confidence_scorer.py:102`）零 AI 调用，按五维度加权：

| 维度 | 权重 | 取值逻辑 |
|:---|:---:|:---|
| source_traceable | 0.30 | `source_quote` 非空=1.0 |
| source_verified | 0.25 | 消费 `_verify_status`：`passed`=1.0，`passed_corrected`/`partial_match`=0.7，否则 0.0 |
| section_covered | 0.20 | 按模块需求条目数/模块段落数比例（`:148`） |
| uniqueness | 0.15 | 1 - 最大 Jaccard 重叠（`:76`） |
| description_specific | 0.10 | 描述长度分档 >80=1.0 / >40=0.7 / >20=0.5 / 否则 0.3 |

档位阈值 `_HIGH_THRESHOLD=0.85`、`_MEDIUM_THRESHOLD=0.60`（`confidence_scorer.py:44`）。此外存在编码惩罚（检出 U+FFFD 乱码扣 0.5，`:228`）。

## 机制五：置信度驱动三车道路由与人工闸门

`step2_breakdown`（`src/pipeline/step2.py`）用评分结果路由三车道（`:637`–`:651`）：

- `conf_score ≥ 85` → `approved`（green），自动通过；
- `60 ≤ conf_score < 85` → `pending_review`（yellow），待人工审核；
- `conf_score < 60` → `blocked`（red），低置信度阻塞。

另设强制审核：`_needs_manual_review` 为真的需求直接进 yellow（`:630`）。车道写 `review_lane` 表（`:764`）。最终闸门由 `self._apply_review_gate` 施加（`:999`）。入库前还有字段完整性门禁，过滤 `module`/`description` 空值（`:690`）。

## 机制六：失败聚类与护栏规则闭环

前五道机制都在"单次拆解内"防幻觉；本机制是跨轮次的**自我修正回路**——把失败用例聚类成模式，再反哺下一次 Step2 的护栏注入。实现位于 `src/extensions/quality/hallucination_logger/`。

- **聚类**：`HallucinationClusterMixin.cluster_failures(intents)`（`_cluster.py:44`）用三条策略归并失败用例：①需求/模块名前缀（前 10 字符相同）；②失败原因命中 `_FAILURE_KEYWORDS`（`:19`，含 点击/登录/弹窗/API/数据库/表单/列表/导航/加载/timeout 等）；③标题 edit-distance（`difflib.SequenceMatcher` ratio > 0.6）。聚类键为 `"{prefix}|{primary_keyword}"`，并经 noise filter 剔除单条簇（`:141`）。`summarize_feedback`（`:149`）把簇渲染成文本，`analyze_and_persist`（`:203`）落库并返回簇报告（`module="cluster_report"`，`:224`）。
- **护栏再生**：Step 执行结束自动触发规则更新——`_run_step.py:673-678` 调 `hallucination_logger.analyze_and_update_rules()`（`_analyzer.py:18`），把聚类结果转为 `test_rules` 表中的防幻觉规则；`test_rules_kb/loader.py:130-159` 以 `source == "hallucination_logger"` 过滤回收这些规则。
- **闭环消费**：`build_step2_guard_injection(chunk)`（`src/pipeline/steps/step2/analyzers/_guard_injection.py:20`）在 AI 提取三元组前注入两段上下文——历史失败反馈（`generate_failure_feedback_prompt`，`_feedback.py:147`，按 `module` 命中）与自动生成的防幻觉规则（`_query_hallucination_guard_rules`，`:41`）。两类注入均非阻断：获取失败静默跳过，不影响 AI 调用（`:7`）。

即闭环为：**失败 → 聚类 → 规则/反馈 → 下次生成前注入**。这是机制一~五之外的第四类防线，属"用历史失败约束未来生成"。

## 设计取舍

- 缩小 AI 作用面（小切片）牺牲了跨切片上下文连贯性，用"扩展切片 + 部分匹配"补偿，但跨片长依赖仍可能漏判。
- 置信度用结构指标而非多视角 AI 辩论，降低了 token 成本与延迟，代价是隐性需求（L2/L3）无法被原文校验，依赖信任等级跳过。
- 三车道阈值 85/60 与 Step4 终判阈值 0.70 是两套独立口径，前者管"需求是否可信"，后者管"用例是否真通过"，不可混用。
