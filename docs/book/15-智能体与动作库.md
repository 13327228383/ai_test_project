# 第 15 章　智能体与动作库

## 概述

`AgentExplorer`（`src/agent/explorer.py:53`）是 Step4 执行期的覆盖驱动探索代理，对标 BrowserGym/WebVoyager。它对外暴露三拍接口：`explore`（覆盖决策）、`replay`（缓存重放）、`repair`（失败修复），其中实时执行走 `execute_intent`。

`AgentExplorer` 通过多重继承组合 5 个 mixin（`src/agent/explorer_mixins/__init__.py:5`），每个 mixin 单文件实现、上限约 800 行（`explorer.py:7`）。`_action.py` 是其中唯一的超长文件，实测 4284 行（`wc -l`）。

`testing_methods/` 是独立的测试方法引擎，产出用例步骤与断言；`browser_tools/` 的动作注册表在第 11 章已覆盖，本章只讲智能体如何消费动作库。

- **定位策略**：`_execute_trigger_click`（`_action.py:510`）内依次串联四条兜底链——Tab 探索（`:587`）、页内导航（`:605`）、Playwright 直接定位（`:625`）、侧边栏与 NavMap（`:675`、`:681`）；快速路径 `_match_elements_smart` 定义在 `_element.py:42`。guided 路径的定位走 `_guided_locate:2987`。

## 三、智能体与 LLM 的交互协议

调用点统一走 `src.ai.router_module` 的 `router.route`。`_llm_decide_next_action` 在 `_llm.py:368` 调用：

```python
from src.ai.router_module import router
_result = await asyncio.to_thread(
    router.route, _prompt,
    system_prompt="你是Web自动化测试Agent……只返回JSON……",
    task_type="general", expect_json=True,
    temperature=0.0,
    seed=(None if (_seed_v := _cfg_seed("ai_stability_seed", 42)) is None else int(_seed_v)),
    max_tokens=2000,
)
```

**提示构造**（`_llm.py:335–365`）：拼接操作目标、期望反馈、页面描述（截断至 2000 字）、最近 5 步历史动作、当前步骤号/上限，再附「铁律」约束与决策优先级规则，最后给出返回 JSON schema：`{action, target, reasoning, found, evidence, value}`。

**返回解析**（`_llm.py:386–408`）：成功取 `data`；若 `data` 为字符串则 `json.loads`，失败转发 `_extract_json_from_text`（`:30`）。该函数策略 1+2 委托 `src.ai.json_parser.parse_json_response` 唯一真源，策略 3 用正则兜底抽取 `action`/`target`/`found`。

**失败处理**：LLM 调用失败或解析失败返回 `None`（`_llm.py:409–412`），由探索循环 `break` 或策略级联的下一路径接管；LLM 调用本身无 in-call 重试。`SemanticMixin` 的语义匹配同样经 `router.route`（`_semantic.py:98`、`:210`、`:310`、`:413`），协议一致。

## 四、testing_methods 的 12 个方法与路由/过滤

`__init__.py:15–37` 导出 12 个方法类：黑盒 8（等价类 EP、边界值 BV、因果图 CE、判定表 DT、正交实验 OT、状态迁移 ST、场景法 FD、错误推测 EG）+ 白盒 4（语句覆盖 SC、分支覆盖 BC、条件覆盖 CC、路径覆盖 PC）。统一接口在 `base.py`：`BaseMethod.analyze:56`、`generate_cases:68`、`run:81`；用例载体 `TestCase`（`base.py:15`）含 `steps:[{action,target,value,desc}]` 与 `assertions:[{type,target,desc}]`。

**MethodRouter 路由判据**（`method_router.py:35`）：

- `ROUTE_TABLE`（`:39–83`）按 7 类需求给出方法组合与优先级，未命中时回退 `complex`（`:126`）。
- `FEATURE_PATTERNS`（`:86–93`）为六类需求的正则关键词。
- `_classify_requirement`（`:161–181`）：关键词计分取最高，单类命中 ≥3 返回该型；≥3 类各有命中返回 `complex`；否则取最高分类型；无命中默认 `crud`。
- `_assess_complexity`（`:183–216`）：基础分 1，文本长度（>500、>2000）、复杂度关键词、页面元素数（>30、>80、iframe、表单数 >10）累加，≤2 为 low、≤5 为 medium、否则 high。
- 白盒方法需 `code_available`，否则低复杂度跳过（`:130–137`）。
- `_estimate_case_count`（`:218–235`）：各方法基数 × 复杂度系数（low 0.5 / medium 1.0 / high 1.5）。

**TaxonomyFilter 三级漏斗**（`taxonomy_filter.py:126`）：`ACTION_TAXONOMY`（`taxonomy_filter.py` 内的本地副本）37 项 + `ASSERTION_TAXONOMY` 的 ui/api/db 合计 35 项，模块文档称共 72 种（`taxonomy_filter.py:130`），目标压到 10–20 种（`:130`）。

- **L1 页面结构扫描**（`_layer1_page_scan:195`）：无结构返回基础集 7 项（`:199`）；按元素 tag 推断可用操作；结构保底 `_STRUCTURAL_FLOOR={"navigate","wait"}`（`:109`）恒保留。
- **L2 需求语义分析**（`_layer2_requirement_scan:262`）：无需求返回 5 基础断言（`:266`）；按关键词匹配 UI/API/DB 三轨断言。
- **L3 方法适配裁剪**（`_layer3_method_adapt`）：按 `method_name` 收口。
- `page_structure_missing`（`:123`）在结构缺失时置真，向调用方暴露「L1 仅用保守默认集」。

## 五、动作库与智能体的关系

数据流：Step3 / `testing_methods` 产出用例（`steps` 动作序列 + `verifications` 断言），`AgentExplorer.execute_intent`（`explorer.py` 策略段）接收 task（含 `_execution_guide` 或 `operation`）。

分派（`explorer.py:382–526`）：`_execution_guide.mode=="guided"` 走 `_execute_guided`（`:391`）；否则 `classify_operation` 按 `op_type` 分派到 search / create / edit / delete / import_export / generic（`:465–526`）。

执行：ActionMixin 方法把抽象动作翻译为 `element_utils` 的 Playwright 原语（`click_button`、`get_page_snapshot` 等）完成真实操作。

回灌：动作方法返回 `dict{success, evidence, actions_taken, strategy, error, _semantic_verdict}`。guided 成功时写入 `op_cache_v2`（`explorer.py:409–426`）供 `replay` 命中；断言结论进入 Step4 验证层判定。动作库（`browser_tools/_tool_definitions.py` 注册表 + `taxonomy_filter.ACTION_TAXONOMY` 37 项词汇）是定义与注册层，智能体是解释与执行层——注册表结构见第 11 章。

## 设计取舍

- 多重继承拆分 mixin（每文件 ≤800 行，`explorer.py:7`）而非单大类，边界隔离利于逐文件复核。
- 策略级联把廉价确定性的「关键词/Tab/侧边栏」放在昂贵的「LLM 探索」之前（`_action.py:647–689` 注释），降低 LLM 抖动与单次耗时。
- LLM 调用固定 `temperature=0.0` + `seed`（`_llm.py:382–383`）换取探索路径确定性，代价是探索多样性下降。
- 分类学三级漏斗用减法压缩 prompt token（72→10–20，`taxonomy_filter.py:130`），代价是结构缺失时退化为保守默认集（`page_structure_missing`）。
- `__init__.py` 导出 12 方法与 `catalog.py` 声明 18 码冲突（见待核实），是口径不一致的代价。
