# 第 26 章　部署与运行

## 概述

工程提供两类运行入口：`main.py` 是引擎通用 CLI（完整 AI 流水线 / 靶子实证），`run.py` 是配置驱动的靶子 E2E 便捷入口（源于 `targets.json`）。打包由 `SmartShopEngine.spec`（PyInstaller 目录型 bundle）与 `Dockerfile`（容器化 Web 控制台）支撑。版本号由 `src/version.py` 作为单一事实源。

## main.py 的子命令

`build_parser`（`main.py:103`）用 `add_subparsers(dest="mode", required=True)`（`:108`）建立两个必填子命令：

- `project`（`main.py:110-117`）：参数 `--project`（必填）、`--from`（默认 1）。落到 `_cmd_project`（`:39-43`），调用 `run_full_pipeline(project, from_step=...)` 跑完整 AI 流水线 Step1→5。
- `target`（`main.py:119-129`）：参数 `--target`（必填）、`--mode`（browser/api/authz）、`--report-dir`、`--out`、`--perf-recalibrate`。落到 `_cmd_target`（`:46-100`），构造 `VerificationPlan(target_key=...)` 并 `execute(...)`；`--perf-recalibrate` 把 `perf.update_baseline=True` 注入 `cfg_overrides`（`:71-72`）供周期校准。
- 兼容旧形态 `main.py --project <name>`（`:132-147`）：顶层 `--project`/`--target` 映射回对应子命令。

退出码在 docstring 声明为 0=成功、1=参数错误、2=门禁阻断/执行异常、3=待人工审核（`:16`）。实测 `_cmd_target` 在 `all_pass` 为 False 时返回 2（`:98-100`），但全文件未出现 `return 3`，见「待核实」。

## run.py 与 main.py 的区别

`run.py` 不执行流水线，而是按 `targets.json` 调度各靶子的 E2E 脚本：

- `--list` 列出靶子与解释器可用性（`run.py:61-73`）；`--target <name>` 跑单个；不带参则顺序跑全部 `enabled` 靶子并汇总（`:108-119`）。
- `run_one`（`:76-105`）用 `subprocess.run([venv_python, script])` 起 `examples/<t>/e2e_pipeline.py`，解释器默认回落到 `target_systems/hospital_sut/.venv/Scripts/python.exe`（`DEFAULT_PYTHON`，`:30`）。
- `run.bat`（`:7`）先校验该 venv python 存在，再转发到 `run.py %*`。

区别：`main.py` 面向"引擎能力"（通用流水线/实证）；`run.py` 面向"靶子验收"，新增靶子只改 `targets.json`，不碰代码（见 `run.py:4-11` 注释）。

## 打包：SmartShopEngine.spec

PyInstaller 配置（`SmartShopEngine.spec`）：

- `Analysis(['src/bundle/entry_main.py'])`（`SmartShopEngine.spec:5`）：入口 `entry_main.py` 仅转发到 `src.backend.app.main`（见 `src/bundle/entry_main.py:12`），即打包产物是 Web 控制台而非 CLI。
- `datas=[('src/frontend','src/frontend')]`（`SmartShopEngine.spec:8`）：内嵌前端静态资源。
- `excludes`（`SmartShopEngine.spec:13`）：剔除 `torch/transformers/sentence_transformers/accelerate/.../matplotlib/...` 等重型依赖，embedding 走 ollama/ngram 回退（见 `entry_main.py:4-5`）。
- 产物形态为 `COLLECT`（`SmartShopEngine.spec:36-44`）生成的目录型 bundle，name `SmartShopEngine`，`UPX=True`。注意：配置用 `COLLECT` 而非 `EXE(..., onefile=True)`，产物是文件夹而非单文件 exe，见「待核实」。

## 靶子系统注册与自动拉起

`targets.json` 实测 4 个条目：

| key | kind | port | enabled | 说明 |
|:---|:---|---:|:---|:---|
| `api_demo` | API | 8010 | true | Flask REST 靶子，token 鉴权/CRUD/参数校验 |
| `spa_demo` | SPA | 8020 | true | 纯静态 SPA，hash 路由/localStorage |
| `promo_demo` | Web | 8030 | true | 云书阁商城，故意注入 3 个真实缺陷 |
| `smartshop` | Admin | 8000 | false | SmartShop Django Admin，缺 Django/MySQL 不可用 |

条目字段：`kind/port/description/python/script/cwd/health_url/report/enabled`（+`unavailable_reason`）。注册新靶子只需在 `targets.json` 加条目，`run.py` 的 `run_one` 以子进程自动拉起其 `script`（`:76-105`）。

靶子系统定位：

- `examples/{api_demo,spa_demo,promo_demo,smartshop}/e2e_pipeline.py`：各靶子的 E2E 入口脚本，被 `targets.json` 的 `script` 字段引用。
- `target_systems/hospital_sut/.venv`：所有靶子默认 python 解释器托管处（`run.py:30`、`run.bat:7`），本身是一个靶子工程。
- `target_systems/fullcov_sut`：全量覆盖靶子，含 `app.py/auth.py/blueprints/config.py/db.py/schema.sql/fullcov.db/requirements.md`（实测），用于高覆盖验收；但本快照 `targets.json` 未登记该 key（见「待核实」）。

## 设计取舍

- `main.py` 子命令式 CLI + 旧形态兼容，允许存量脚本与文档平滑过渡。
- `run.py` 把靶子清单外置为 `targets.json`，运维加靶子零代码改动。
- 打包默认 COLLECT 目录 + 去 ML 依赖，换取无 torch 下可启动；代价是目录型分发而非单文件。
- 容器默认暴露 Web 控制台，CLI 作为可选 CMD 覆盖，单一镜像覆盖两种使用形态。

- ~~是否有另一 spec / onefile 配置~~ → **已核实（2026-10-15）：有第二个 spec，但它不是引擎本体的 onefile 版。** `scripts/bundle/_build/SmartShopEngine_Setup.spec:19-25` 是 `EXE(... a.datas ..., name='SmartShopEngine_Setup')`，产出的是**安装器**（`setup_installer.py:9,13` 说明它把 exe/_internal/mariadb/run.bat/.env 解包到安装目录），不是把引擎打成单文件。因此「引擎本体是 COLLECT 目录型产物」这一事实不变，`dist/SmartShopEngine/` 是文件夹而非单文件 exe。真正的一体化交付路径是安装器 Setup.exe → 解包出目录。
- ~~退出码 3 是否由内部返回~~ → **已核实（2026-10-15）：全文无 `return 3`，该退出码不可达。** `main.py:16` docstring 声明"3=存在待人工审核用例"；对全仓 `.py` 检索 `return 3` 的命中全部在 `logs/probes_scripts_2026-10-02/` 等历史探针脚本与 `ModSystem/app/app.py` 内，`main.py` 自身**零命中**。`_cmd_target` 在 `all_pass` 为 False 时返回 2（`:98-100`）。即：存在待人工审核用例时，调用方拿到的是 2（门禁阻断），无法据退出码区分。
- ~~`fullcov_sut` 是否在 targets.json 注册~~ → **已核实（2026-10-15）：确未注册。** `targets.json` 实测顶层 key 仅 **4 个**：`api_demo`、`spa_demo`、`promo_demo`、`smartshop`；全文检索 `fullcov` 出现 **0 次**。即 `target_systems/fullcov_sut/`（8050 端口全量覆盖靶子）不在 `main.py target` 的可选靶子注册表内，只能通过项目流水线（Step1→5）或直接 HTTP 驱动。
