# 第 25 章　质量门禁防线

## 概述

质量门禁由两层构成：常驻静态门禁（落在 `tests/test_core/` 的三个 gate 文件，作为 pytest 用例运行）与提交前钩子（`.pre-commit-config.yaml` 的 5 个 hook）。两层共同落实"反补丁三禁"——禁止重复造轮子、禁止打补丁式分支、禁止保留感染性信息与注释（`AGENTS.md:116-139`）。

`tests/test_core/` 实测 5 个文件、43 个测试函数：`test_duplicate_definition_gate.py`（重复定义）、`test_static_scope_gate.py`（静态作用域越界）、`test_instruction_contract_gate.py`（指令契约）、`test_config_recommender.py`（推荐值算法）、`test_redact.py`（脱敏）。本章覆盖前三个 gate（统称"三禁"落地点）与 pre-commit 配置。

## 门禁一：禁止重复定义

文件 `tests/test_core/test_duplicate_definition_gate.py`。判据两条（见模块 docstring `:9-16`）：

- 规则 A：同一文件内，同名 `_` 前缀 tuple/list/set 字面量（≥2 元素）定义 ≥2 次。判定在 `_scan`（`:55-95`）以 `key = (rel, target.id, canon)` 记录已见常量，`seen` 命中即记入 `rule_a`；`test_no_new_duplicate_constant_in_same_file`（`:98-105`）对 `rule_a - _BASELINE_A` 断言为空。
- 规则 B：同一多元素字符串常量（≥3 元素、各元素以 `'` 开头）以 `_` 前缀名出现在 ≥2 个模块。同一 `canon` 落入 `shared`（`:90-91`），模块数 ≥2 记入 `rule_b`（`:92-94`）；`test_no_new_duplicate_vocabulary_across_modules`（`:108-121`）对 `set(rule_b) - _BASELINE_B` 抛错。

判据机制：AST 静态遍历 `src/`，不执行代码（`:59-68`）；语法错误会直接 `AssertionError`（`:70`）。

## 门禁二：禁止静态作用域越界

文件 `tests/test_core/test_static_scope_gate.py`。判据：对 `src/` 全量运行 ruff，`--select F821,F823`，断言 `returncode == 0`（`:48-67`）。背景列明 F823（局部变量赋值前引用）曾在 `api_only_executor.py`、`parallel.py`、`_base.py`、`serial.py` 复发，并在关键收尾/落库路径运行时才炸（`:4-13`）。

注：docstring 写明"只选 F823"（`:41-46`），称 F821 在本仓有 37 处历史命中、多无害；但代码实际 `--select` 含 `F821,F823`（`:54-55`）。两者文本冲突，见「待核实」。ruff 缺失时 `skipif` 跳过（`:39`）。

## 门禁三：指令契约（防幻觉/假 PASS/假 FAIL）

文件 `tests/test_core/test_instruction_contract_gate.py`，13 个测试函数，把"生成端↔执行端共用事实源"钉死而非逐个打补丁。关键判据：

- 结果语义唯一真值表：`render_check_tag` 对 `{passed:True,skipped:True}` 必须返回 `[SKIP]`（`:38-52`）。
- 三值聚合：`aggregate_check_results` 全为非判定态时 `no_verdict_only=True`（`:55-72`）。
- 生成端咽喉点：`_check_guard.sanitize_intents` 必须剔除契约外 action（如 `count_list_rows`）、剔除类别错配断言、改写语义断言（`:121-145`）。
- 落库边界强制：`case_store` 的 `upsert_intents` 必须调用 `sanitize_case_checks`，静态检查函数体含该符号（`:214-247`）。
- 探针非判定：`db_table_accessed_check` 结果一律落 `[SKIP]`，`is_verdict` 返回 False（`:251-272`）。
- 极性反转：需求本身即错误提示时，`no_error` 反转而非剔除（`:276-312`）。
- 不发射环境探针顶替需求断言：`_gen_api_probe_check`/`_gen_db_probe_check` 返回 None（`:316-328`）。
- 模板文案不污染极性：`strip_engine_template` 去除引擎模板后正向需求不得判为 `expects_error`（`:332-377`）。
- 断言叙述不反向定义操作类型：判定收敛到 `operation`+`actions[].type`（`:381-438`）。
- 变更流序 SSOT：`build_interaction_actions` 产出"开窗→录入→提交"，且两条生成路径都调用它（`:442-522`）。
- auth 导航非空：`_login_entry_url()` 非空且被两个调用点使用（`:526-559`）。

## 提交前钩子

`.pre-commit-config.yaml` 定义 5 个 local hook：

1. `forbid-except-pass`：`scripts/pre-commit/check_except_pass.py`
2. `forbid-sql-injection`：`scripts/pre-commit/check_sql_injection.py`
3. `forbid-innerHTML`：`scripts/pre-commit/check_innerHTML.py`（匹配 `.js` / `.html`）
4. `bandit`：`bandit -c pyproject.toml -ll -q`
5. `forbid-duplicate-definition`：`pytest tests/test_core/test_duplicate_definition_gate.py -q`

钩子 1–3 引用 `scripts/pre-commit/` 下的脚本，但本快照该目录不存在（见「待核实」），钩子运行会失败；钩子 5 直接复用门禁一。

## ratchet 基线机制

重复定义门禁用冻结集合作基线，只减不增：

- `_BASELINE_A = frozenset()`（`:30`）：同文件重复常量存量，2026-10-02 全部清零。
- `_BASELINE_B = frozenset()`（`:31`）：跨模块词表存量，同日清零（21 组已归一为权威源 import）。

新提交若产生任何新重复，即 `rule - _BASELINE` 非空 → 断言失败。基线随存量归并逐步收窄，不允许反向扩大。

## "反补丁三禁"在门禁层的落地

- 禁止重复造轮子 → 门禁一（重复定义）静态拦截，跨模块词表强制收敛到单一事实源。
- 禁止打补丁 → 门禁三以"结构性锁定"落实：多处调用点必须引用同一 SSOT（如 `build_interaction_actions`），局部关键词表被删（`tests/test_core/test_instruction_contract_gate.py:514-522`），新增生产者自动受 `upsert_intents` 边界约束（`:244-247`）。
- 禁止保留感染性信息与注释（事件叙事注释）：在 `CONTRACT.md` §二.5 与 `AGENTS.md:138` 定义为"Fix X(日期)/第N轮修复"式注释；本快照未找到代码层 gate 或 hook 强制它（见「待核实」），属书面纪律约束。

## 设计取舍

- 静态 AST/ruff 门禁不依赖真实运行，能在 CI 最小成本下拦截结构性漂移；代价是只覆盖可静态判定的性质。
- ratchet 基线采用"清零+只减"，避免存量噪声淹没信号；代价是存量归并需人工评审（门禁 docstring 明确 B 存量不得盲目合并）。
- 指令契约门禁以行为级断言 + 静态源检查混合（落库边界、SSOT 调用点用源码字符串判定），以绕过"需要真实 MySQL"的障碍（`tests/test_core/test_instruction_contract_gate.py:224-226`）。
