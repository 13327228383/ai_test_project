# 第 22 章　配置体系

## 概述

配置体系由四层代码构成：`src/core/config_loader/`（13 个加载器模块，门面类 `ConfigLoader` + 注册表 `ConfigRegistry`）、`src/core/config.yaml` 与 `src/core/config.json`（系统级默认）、`src/core/pipeline_config.py`（981 行，流水线集中配置入口）、以及 `src/backend/routes/pipeline_config/` 与 `src/backend/routes/project_config/` 两套 Web 接口。凭据（API Key 等）单独存于 `user_credentials_v2`，经 Fernet 加密，与业务配置隔离。

## 配置分层

| 层级 | 存储 | 优先级 | 粒度 |
|:---|:---|:---|:---|
| 系统级默认 | `src/core/config.yaml` + `config.json` + 代码默认值 | 最低 | 全局 |
| 项目级 | MySQL `project_configs.config_json` | 高于 YAML/JSON | 项目 |
| 用户/运行时覆盖 | `pipeline_user_config`、运行期 `_set_runtime`、环境变量 | 最高 | 用户 / 进程 |

加载顺序在 `base.py` 明确：`_load_system_yaml()`（`:134`）→ `_load_config_json()`（`:156`，非空值覆盖 YAML）→ `_load_project_config()`（`:193`，MySQL `project_configs` 覆盖）。`_get()` 取值优先级为：环境变量（`_ENV_KEY_MAP`/直读）→ 运行期覆盖 `_runtime_overrides` → `_config_data` → `_YAML_KEY_MAP` 别名（`base.py:306-329`）。

## 配置读取与校验（ConfigRegistry / ConfigLoader）

- 门面拆分：`ConfigLoader`（`config_loader/__init__.py:76-99`）继承 11 个 mixin（`ai`/`confluence`/`figma`/`target`/`playwright`/`database`/`smart_session`/`project_meta`/`api_docs`/`pricing` + `base`），对外属性访问 100% 兼容。
- 取值器：`_get(key, default)`（`base.py:306`）、`_set_runtime(key, value)`（`:331`）、`get_all()`（`:378`）、`__getattr__`（`:381`，先查运行期覆盖与 `_config_data`，再查 YAML 原名/小写）。
- 类型转换：`_coerce_env_val`（`:282`）按 default 类型把环境变量字符串转 bool/int/float，修正 `bool("false")==True` 的坑。
- 注册表隔离：`ConfigRegistry`（`config_loader/__init__.py:141-248`）按 project 维护 `dict[str, ConfigLoader]`，`for_project()` 用 double-checked locking 避免并发串行化（`:180-200`）；`__getattr__` 把属性访问委托给当前项目的 loader（`:245-248`）。
- 当前项目来源：`_current()` 优先 thread-local `_current_project`（来自 `src/backend/state`），回退 `_default_project`，再回退进程级 `_global_project`（`:209-231`，修复 asyncio 工作线程无上下文时落到空实例的问题）。

## pipeline_config.py 集中入口

`src/core/pipeline_config.py` 是流水线参数的统一读取入口，声明自身优先级为「用户 DB 配置 > 环境变量 > 默认值」（`:1-5`）。用户级配置存于 `pipeline_user_config` 表，读取带 5 秒 TTL 缓存（`:41-45`），模块内 `CREATE TABLE IF NOT EXISTS` 兜底建表（`:86-99`），键大小写归一（精确→大写→小写，`:116-119`）避免落库不生效。

## pipeline_config 接口与 project_config 接口的区别

| 维度 | `project_config`（项目配置） | `pipeline_config`（流水线配置） |
|:---|:---|:---|
| 作用对象 | 被测系统/项目级参数（TARGET_URL、DB 连接、Figma/Confluence Key 等） | 流水线各 Step 调优参数（分片大小、阈值、RAG 权重等） |
| 存储表 | `project_configs`（`config_json`） | `pipeline_user_config`（user_id+config_key） |
| 粒度 | 项目 | 用户（可随项目自动套用推荐值，`source`=manual/auto） |
| 校验 | `_VALID_CONFIG_KEYS` 白名单（`project_config/fetchers/constants.py:33`） | `CONFIG_SCHEMA` 动态表单 schema（`pipeline_config/_routes.py:45`） |
| 历史/回滚 | 有：`/api/config/history`、`/api/config/rollback`，落 `config_history` 表 | 无独立历史路由 |
| 路由文件 | `project_config/project_config.py:59-76` | `pipeline_config/_routes.py` |

`project_config` 提供 `/api/config` 读写 + `/api/config/history` + `/api/config/rollback`（`project_config.py:59-76`），写入经 `_coerce_config_value` 类型化；`pipeline_config` 的 `_routes.py` 以内置 `CONFIG_SCHEMA` 向前端下发分组表单（`_routes.py:42-45`），前端按 schema 动态渲染。

## 凭据隔离（user_credentials_v2）

- 存储：用户 API Key / 模型偏好等敏感配置存 `user_credentials_v2`，`(user_id, project, key)` 主键，`value` 为密文（`schema.sql:116-126`）。
- 加密：`users/auth/encryption.py` 用 **Fernet** 对称加密（`_encrypt`/`_decrypt`，`:234-251`），密钥标志 `encryption_key_v2` 存于 `system_config` 表（`encryption.py:11`）。
- 密钥获取优先级（`_load_or_create_key`，`:148-231`）：内存缓存 → MySQL `system_config` → 环境变量 `ENCRYPTION_KEY_V2` → 本地备份 `docs/encryption_key_recovery/encryption_key_v2.bak` → 仅在 `user_credentials_v2` 无密文（确认首次启动）时才生成新密钥，否则抛 `RuntimeError` 拒绝覆盖（`:202-212`）。
- 隔离与回退：`credentials.get_user_credential`（`users/credentials.py:34`）查找顺序为「当前项目 → 当前用户全局(`*`) → 管理员全局(`*`)兜底」，凭证与业务配置分表、密文存储，业务配置不接触明文密钥。
- 轮换：`rotate_encryption_key()`（`:273`）解密重加密全部凭据并回写新密钥。

## 设计取舍

- 配置分层 + 单一事实源：系统默认走 YAML，项目覆盖走 MySQL，避免散落 `.py`，代价是读取需合并多源。
- 凭据与业务配置分表分通道：敏感字段 Fernet 加密且三级回退查找，业务配置明文 JSON 直存，安全面与易用面解耦。
- `ConfigRegistry` 按项目隔离而非全局单例：支持多项目并发，代价是 double-checked locking 与 thread-local 复杂度。
