# 9. 续修（23:00–23:20）：RC-AQ / RC-AR / RC-AO 挂钩点纠偏

## 9.1 RC-AO：上一轮的修复挂在了一条没人走的路上（自我纠错）

**发现**：引擎日志中 `_call_api` 内部的 `"[智能调节]"` 出现 **0 次**，
而 `router_module` 的 `"路由:"` 出现 **4 次**。

**结论**：真实 AI 调用**直连 `Router.route()`**（全库仅 6 处调用点），
我上一轮挂钩的 `_call_api` 根本没被走到 → 看门狗修复无效。
（22:47:07 在引擎重启之后仍触发过一次"强制释放执行槽"，即为反证。）

**正确收口 = 两处都挂**（覆盖不相交的两条出网路径）：

| 挂钩点 | 覆盖路径 |
|---|---|
| `src/ai/router_module/_router.py::Router.route` | 走 Router 的全部 6 个调用点 |
| `src/ai/ai_client_mixins/_base.py::_call_api` | `use_router=False` / 无 `task_type` / Router 抛异常后的直连 Provider 分支 |

**「在飞」改为心跳制**（原为进入时算一个静态截止时刻）：
一次 `route()` 内含云端重试，总耗时 = `(N+1)×超时 + 退避`，静态上界要么算不准、
要么为保险而放宽到形同虚设。心跳每半周期（10s）续期一次，语义严格等于
"此刻确有请求在网上"。另设硬上限 `timeout + 30s 宽限`，防止 Provider 超时被误配成
无穷大而获得永久豁免。

**看门狗语义改正**：从「拉长预算」改为「**重置空闲计时**」——
拉长预算只是把误杀点往后挪。

## 9.2 RC-AQ：登录语义判定不辨否定语境（实证）

`is_login_operation()` 是纯子串匹配：

```
operation = "验证未登录访问业务页面"      → 含"登录" → 判 login  ✗
expected  = "系统重定向到登录页（302），拒绝业务数据返回"
```

判为 `login` 后套用登录模板，生成验证点
**"错误凭证被拒绝，提示错误信息/登录失败"** —— 需要**提交错误的用户名密码**，
而该需求的真实语义是**未认证直接访问 URL 应被重定向**。
**验证点与期望自相矛盾 → 引擎自造假 FAIL。**

**修**：新增否定/终止语境正则先行剥离
（`未/无/非/尚未/没有` + 认证词；`退出/登出/注销`；`登录超时/失效`），
使其落到 `access_control` 分支。

**实测对比**：

| 需求 | 修复前 | 修复后 | 判定 |
|---|---|---|---|
| REQ-016「验证未登录访问业务页面」 | `login` | `access_control` | ✓ 修正 |
| REQ-019「未登录访问业务页面」 | `login` | `access_control` | ✓ 修正 |
| REQ-040「登录失败（用户名或密码错误）」 | `login` | `login` | ✓ **未被误伤** |

最后一行是关键：REQ-040 是**真的**登录失败场景，修复不能把它一起改掉。

## 9.3 RC-AR：需求没点名受限动作时，引擎凭空造一个「新增」（最严重）

```python
_verbs = [v for v in (verbs or []) if v] or ["新增"]   # ← 凭空造动作
```

**实证链（REQ-005，需求原文「审计日志功能仅对 admin 角色开放，非 admin 用户请求访问时系统应拒绝」）**：

1. `_restricted_actions()` 扫不出任何受限动词（需求只说"拒绝访问"）→ 返回 `[]`
2. `or ["新增"]` 兜底 → 用例拿到"新增"这个**需求里根本不存在的动作**
3. 用例导航到资产页、点击"新增资产"、断言"应被拒绝"
4. 执行身份是 admin，**admin 本就允许新增资产** → 判"越权未被拒绝/越权成功"

> **这是引擎自造的假 Bug —— 靶子毫无缺陷。**

**修**：未点名动作时不再造假动作，只导航 —— 受限对象就是**页面本身**（访问即应被拒）。

## 8. 纪律反思

本轮**第三次**栽在同一类错误上：改动里引用了当前文件并不存在的名字。
`py_compile` 只查语法、不查名字解析，加上函数内 `try/except: pass` 会把 `NameError`
吞成"静默降级"，现象看起来跟"修复没生效"一模一样。

**已固化为自检动作**：凡新增对模块级名字的引用，改完必须 grep 确认该名字在本文件
import 行中存在；跑通 `py_compile` 不等于跑得起来。
